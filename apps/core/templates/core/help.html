{% trans "Tickets" %}

  • {% trans "Every ticket has a key made of the project key and a number, for example MPR-12." %}
  • {% trans "Create a ticket from a project's Issues page with + Create issue. Choose its type: epic, story, task, bug, sub-task or test." %}
  • {% trans "Assign it to a project member, set a priority, story points and a due date, and link it to an epic or a parent." %}
  • {% trans "Comments support Markdown. Type @handle to mention a teammate; they get a notification." %}
  • {% trans "Use the search box at the top (or press /) to find a ticket by text or jump straight to a key such as MPR-12." %}

{% trans "Import tickets from a file" %}

{% trans "You can create many tickets at once from Excel, CSV or JSON." %}

  1. {% trans "Open the project and go to Issues → Import CSV." %}
  2. {% trans "Download the template in the format you like: Excel (.xlsx), CSV or JSON. The template has the right columns and example rows." %}
  3. {% trans "Delete the example rows and fill in one ticket per row." %}
  4. {% trans "Upload the file. If any row has a problem, nothing is imported and every problem is listed with its line number. Fix them and upload again." %}

{% trans "Columns" %}

  • issue_type, title {% trans "(required)" %}
  • description, priority (highest, high, medium, low, lowest), assignee ({% trans "email or handle of a member" %})
  • epic, parent ({% trans "issue keys, e.g. MPR-1" %}), sprint ({% trans "name of an open sprint" %})
  • story_points, due_date (YYYY-MM-DD)
  • labels, components, fix_versions ({% trans "names separated by ;" %})
  • cf_<key> ({% trans "a custom field of the project" %})

{% trans "Limits: 500 rows and 1 MB per file. Every new ticket starts in the project's starting status." %}

{% trans "Board and columns" %}

  • {% trans "The Board shows the tickets of the active sprint, or all open tickets with ‘All issues’. Drag a card to another column to move it." %}
  • {% trans "Drag and drop only accepts moves the workflow allows. A card dropped on a column moves to that column's first status." %}
  • {% trans "Project managers and admins can change the columns with ⚙ Columns: move a column up or down, rename it, add or delete columns." %}
  • {% trans "Every status belongs to exactly one column. When you delete a column, choose where its statuses go." %}

{% trans "Statuses and workflow" %}

{% trans "Project managers and admins can change the statuses of a project from ⚙ Columns → Add or change statuses & workflow." %}

  • {% trans "Add status:" %} {% trans "give it a name, pick the board column it goes to, and tick ‘Counts as done’ if finished tickets should be marked as done." %}
  • {% trans "Start:" %} {% trans "the status new tickets begin in. Exactly one status is the start status." %}
  • {% trans "Counts as done:" %} {% trans "tickets in these statuses are resolved, leave the open lists, and count as completed in sprints and epics." %}
  • {% trans "Transitions table:" %} {% trans "a checked box means a ticket may move from the row status to the column status. Every status needs at least one exit." %}
  • {% trans "Delete status:" %} {% trans "its tickets move to the status you choose. The start status can't be deleted." %}

{% trans "API keys" %}

  1. {% trans "Open your profile (your name at the top right) and go to API keys." %}
  2. {% trans "Enter a name, for example Claude, and optionally tick Read only or set an expiry in days. Click Create key." %}
  3. {% trans "Copy the key right away. It starts with mpk_ and is shown only once. Mpira keeps only a fingerprint of it." %}
  4. {% trans "To stop a key from working, click Revoke next to it. Anything using the key stops working immediately." %}

{% trans "A key has the same project access you have. Use a read-only key whenever writing isn't needed." %}

{% trans "Connect Claude" %}

{% trans "The Mpira MCP server lets Claude read and write tickets for you. It needs Python 3.10 or newer and your API key." %}

{% trans "1. Get the server" %}

{% trans "The server is in the tools/mpira-mcp folder of the project. In that folder run:" %}

pip install -r requirements.txt

{% trans "2a. Claude Code" %}

claude mcp add mpira \
  -e MPIRA_URL={{ base_url }} \
  -e MPIRA_API_KEY=mpk_your_key_here \
  -- python "C:/path/to/tools/mpira-mcp/server.py"

{% trans "2b. Claude Desktop" %}

{% trans "Open Settings → Developer → Edit config and add this to claude_desktop_config.json, then restart Claude:" %}

{
  "mcpServers": {
    "mpira": {
      "command": "python",
      "args": ["C:/path/to/tools/mpira-mcp/server.py"],
      "env": {
        "MPIRA_URL": "{{ base_url }}",
        "MPIRA_API_KEY": "mpk_your_key_here"
      }
    }
  }
}

{% trans "3. Ask Claude" %}

  • {% trans "“What are my open tickets?”" %}
  • {% trans "“Create a high priority bug in MPR: the checkout total is off by one cent, assign it to nikos.”" %}
  • {% trans "“Move MPR-14 to in progress and comment that I've started.”" %}

{% trans "The key is stored in your own Claude settings file. Don't share that file, and revoke the key if it leaks." %}

{% trans "Using the API directly" %}

{% trans "Send the key in the Authorization header. The base address is:" %} {{ api_base }}

curl -H "Authorization: Bearer mpk_your_key_here" {{ api_base }}issues/?assignee=me&open=true
curl -X POST -H "Authorization: Bearer mpk_your_key_here" -H "Content-Type: application/json" \
     -d '{"title":"New bug","issue_type":"bug"}' {{ api_base }}projects/MPR/issues/
curl -X POST -H "Authorization: Bearer mpk_your_key_here" -H "Content-Type: application/json" \
     -d '{"status":"in_progress"}' {{ api_base }}projects/MPR/issues/14/transition/

{% trans "Errors always look like {error: {code, message, details}}. A wrong or revoked key returns 401, and a read-only key that tries to write returns 403." %}
